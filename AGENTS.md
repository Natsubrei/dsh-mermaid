# dsh-mermaid-panel

A DeepSeek Harness client plugin: one right-Sidebar page type that renders the
Mermaid diagrams in the conversation on screen. The chat's own code block is
left as written, so copying or quoting the source keeps working.

The package is `dsh-mermaid-panel` because `dsh-mermaid` belongs to
[MrmoLabs/dsh-mermaid](https://github.com/MrmoLabs/dsh-mermaid), which renders
inside the messages instead; both install together.

## Map

- `src/client.jsx` — the whole browser half: page type, DOM scan, cards, zoom/pan.
  The source. `client.js` is its build output, never the place to edit.
- `client.js`, `client.mermaid.js` — artifacts, committed, so a Git install needs
  no build. `client.mermaid.js` is the 3.5 MB engine, requested on first diagram.
- `build.mjs` — esbuild. Both module ids come from `package.json.name`.
- `cordis.patch.yml` — the profile entry. Its `id` and `name` are the package name.
- `index.json` — this repository's market index, generated by
  `scripts/market-index.mjs`. Hand-editing it is always wrong.
- `index.js` — host half. Empty on purpose: rendering is browser-only.

## Change something

1. Edit `src/client.jsx`.
2. `npm run build`, then `grep -m1 '  id: "' client.js`: it must equal the
   `package.json` name, because that name is also the engine chunk's id
   (`dsh-mermaid-panel/client.mermaid.js`) that `require.async` resolves.
3. `node --check client.js` — a bundle that does not parse is otherwise only
   visible in the GUI.
4. Install this directory into a scratch profile
   (`plugin_manager install_bundle <dir>`) and hard-refresh the Web GUI. Client
   plugins reach the page at load, so a refresh applies them and a host restart
   does not.

There is no test suite; step 4 is the test. Mermaid's own parser is the final
word, so a source that fails renders as the failure notice plus its source.

## Release

The market entry pins a commit, so the tag, the tarball, and the index must all
describe the same code.

1. Bump `version` in `package.json`, `npm run build`, commit the bump with both
   artifacts (`Release 0.2.0`).
2. `git tag v0.2.0 && git push origin main --tags`.
3. Pack outside the tree under an unversioned name, then publish the release:

   ```bash
   npm pack --pack-destination /tmp/dsh-rel
   cp /tmp/dsh-rel/dsh-mermaid-panel-0.2.0.tgz /tmp/dsh-rel/dsh-mermaid-panel.tgz
   gh release create v0.2.0 /tmp/dsh-rel/dsh-mermaid-panel.tgz --title v0.2.0 --notes '…'
   ```

   `releases/latest/download/dsh-mermaid-panel.tgz` is a permanent URL the market
   index and the awesome-list entry point at, so the asset keeps that name.
4. `npm run market` on the tagged commit — it refuses when `client.js`'s module id
   disagrees with the package name — then commit `index.json` alone
   (`Publish the 0.2.0 market index`) and push. It pins the tagged commit, never
   the index commit, so regenerate only when the artifacts move.
   `MARKET_COMMIT=<sha> MARKET_TIMESTAMP=<unix>` covers generating it first.
5. `npm publish`. A new name answers `PUT 202` and serves npm's `0.0.0-stage`
   placeholder for a minute or two while the tarball is processed, so
   `npm view <name> version` can answer `0.0.0-stage` for a publish that worked:
   read `dist-tags.latest`, which must equal the tagged version. A publish that
   fails after the tag is retried as a publish, never as a new tag.

## Distribution

- npm `dsh-mermaid-panel` — `install_bundle dsh-mermaid-panel@0.1.4`. This is the
  install path behind a slow GitHub connection, and awesome-dsh-plugin's
  `probe-npm.mjs` upgrades its card to a registry install once the package exists
  and its `repository` points back here.
- Market index:
  `https://raw.githubusercontent.com/Natsubrei/dsh-mermaid-panel/main/index.json`
  — added in Plugins → Discover → Add index, with Discover's **Custom plugin
  markets** switch on first.
- awesome-dsh-plugin entry: `data/plugins/Natsubrei__dsh-mermaid-panel.yml`. Its
  `url`, `name`, and `tarball` track the repository name and the release asset, so
  a rename is an edit in that repository's pull request.
- Keep `Natsubrei/dsh-mermaid` unclaimed: the old links redirect only while the
  name stays free.

## Gotchas

- Internal ids are keys, not names: the tab id `dsh-mermaid/mermaid`, the locale
  namespace `mermaid`, and the `dsh-mermaid-*` class names survive a package
  rename. Changing the tab id only resets an open Sidebar tab.
- The page reads the DOM the chat has mounted. When "no diagrams" is reported,
  check the code-card selectors in `src/client.jsx` before any plugin code: chat
  markup changes first, and the page's empty state is the symptom.
- Mermaid's engine is a classic script. `build.mjs` keeps it out of the module
  factory, because wrapping it drops the global it installs.
